# basegames — оверлей-подсказчик для 2048

Читает доску 2048 прямо с экрана и рисует поверх неё стрелку с лучшим ходом.

Основная реализация — на C++ под Windows: один самодостаточный `.exe`, без
внешних зависимостей. Питоновская версия оставлена как эталон, с которым
сверяется решатель.

```
cpp/        основная реализация: Win32 + GDI+, битборд
python/     эталонная реализация: mss + OpenCV + PyQt6
testdata/   общий набор позиций и ожидаемых ходов для сверки
```

## Как это работает

| Слой | C++ | Python |
|---|---|---|
| Захват | `BitBlt` в DIB | `mss` |
| Поиск доски | заливка по цвету фона | контуры OpenCV |
| Чтение клеток | доминирующий цвет + палитра | то же на numpy |
| Решатель | битборд + expectimax | кортежи + expectimax |
| Оверлей | слоёное окно `UpdateLayeredWindow` | PyQt6 |

Распознавание обходится без OCR: в классической вёрстке 2048 у каждого номинала
плитки свой уникальный цвет фона, поэтому клетка читается сопоставлением
доминирующего цвета с таблицей.

Решатель на C++ пакует доску в один `uint64_t` — по 4 бита на клетку, в нибле
показатель степени. Ходы строк предпросчитаны для всех 65536 вариантов, так что
ход по доске сводится к четырём обращениям к таблице.

## Сборка C++

Нужен MSVC с рабочей нагрузкой «Разработка классических приложений на C++»
и Windows SDK. Из «x64 Native Tools Command Prompt for VS»:

```bash
cmake -S cpp -B cpp/build -G "Visual Studio 17 2022" -A x64
cmake --build cpp/build --config Release
```

Запуск — `cpp\build\Release\smt.exe`. Выход по **Ctrl+Alt+Q**: окно сквозное и
своих элементов управления не имеет.

Тесты, включая сверку с эталонными ходами из `testdata/`:

```bash
ctest --test-dir cpp/build -C Release --output-on-failure
```

## Запуск Python-версии

```bash
py -m pip install -r python/requirements.txt
py python/src/main.py
```

Флаги: `--monitor N`, `--depth N`, `--interval S`.

Тесты:

```bash
py -m pytest python/tests -q
```

## Сверка реализаций

`testdata/positions.txt` — 40 позиций из реальных партий,
`testdata/expected_moves.txt` — ходы, выбранные питоновским решателем на
фиксированной глубине 4. Обе версии считают одну оценочную функцию тем же
порядком обхода, поэтому обязаны совпадать; C++-тест это проверяет.

Перегенерировать эталон:

```bash
py python/tools/reference_moves.py > testdata/expected_moves.txt
```

## Заметки

- **Глубина поиска адаптивная**: чем меньше пустых клеток, тем глубже смотрим,
  потому что ветвление падает вместе с их количеством.
- **Окно не перехватывает ввод** — играть можно как обычно.
- **DPI**: C++-версия объявляет себя per-monitor DPI aware, поэтому координаты
  захвата и отрисовки совпадают при любом масштабе экрана.
- **Кириллица в консоли Windows** может падать на cp1252. Если ловите
  `UnicodeEncodeError` в питоновской версии, выставьте `PYTHONIOENCODING=utf-8`.
- Fullscreen exclusive приложения захватить не получится — 2048 в окне браузера
  проблем не вызывает.
